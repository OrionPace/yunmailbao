系统使用准则与架构介绍 (v2.0)

📖 数据模板规范

目标受众 Excel 请严格按照如下规范整理，这决定了引擎能否正确提取：

  • 第一列 (A列)为收件人姓名 (例: 张三)。程序会在正文中替换 <人名> 为该列的值。
  • 第二列 (B列)为收件人邮箱 (例: example@163.com)。
  • 请确保表格不要有合并单元格以及隐藏行。

⚡ 防封禁与到达率策略 (必读)

使用 SMTP 授权码自动发送本质等同于模拟网页点击发送。如果您在短时间内极高频地对外域同种邮箱发起轰炸：

  • 发送行为会被大厂捕获： 网易、腾讯等具有极其敏感的同 IP 高频发信检测机制。
  • 策略配置： 我们允许用户在主页面配置 一次性并发量 (默认1)。如果您设置为 30，系统将会在瞬间连同抛出30个信道，但这会极大幅增加进垃圾箱甚至当场挂掉账号的风险。
  • 推荐做法： 轮转准备 3 到 5 个发件邮箱池，单次并发维持在 1 或 2，设置每次发送的抖动间隔最少 5~15 秒，以追求极高的送达率 (Inbox Rate)，而不只是单纯追求速度。

🖌️ 富文本特色

改版后的 Quill 引擎已经支持：

  • 将微信/QQ截图直接 Ctrl+V 贴入编辑光标处，内部会自动转码为 Base64 与文字同传，无需当做独立附件。
  • 提供中文字体（如 微软雅黑, 宋体）以及标准字号排版（如 小四[16px]）。

👥 研发背书

本系统技术栈经过升级重构。

  • 基础架构技术： FastAPI (Python) + pywebview + 纯原生 ES6。
  • 界面体验与智能内核驱动： 联合 Gemini 3.1 Pro 参与设计迭代、OrionPace、及前序 Claude opus4.6 的开发基因协同构筑。
  • UI指导基准： 采用 Catppuccin (Latte / Macchiato) 行业顶尖护眼美学体系。
