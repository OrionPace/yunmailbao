## 1. 现状与问题

更新日期：2026-10-12。产品名称为 **云邮宝 YunMailBao**，源码仓库为 [OrionPace/yunmailbao](https://github.com/OrionPace/yunmailbao)。仓库更名不改变本地 `auto_email` 目录，也不迁移安装身份或用户数据。`0.2.1` 为本轮候选目标，不是已发布版本；旧 `0.2.0` 的验收记录不能作为本版通过证据。

目标用户是培训、会议与活动组织者。需要解决的是按名单字段核对发送范围、复用个性化内容、保留可追溯结果，并处理拒绝和不明提交；不是绕开服务商限制或保证收件箱投递。

| 工作流 | 边界 |
| --- | --- |
| XLSX/CSV 导入、列映射、多值筛选、名单预检 | 多列条件取交集，同列多值取并集；显示无效、重复、排除和姓名冲突，冲突阻止创建任务。 |
| 冻结收件人、行变量、主题/正文、账号配置与附件摘要 | 草稿修改不改写已冻结任务，发送前仍复查排除名单。 |
| 思源黑体富文本、表头变量、纯文本/CID 图片与 PDF/DOCX/XLSX/PPTX 单附件 | 附件原名进入 MIME；文件格式及体积受限。预览不能证明所有邮件客户端的真实排版。 |
| SQLite 逐人状态、尝试账本、恢复、导出 | SMTP 接受只表示提交；提交结果不明保留待确认，不提供 exactly-once 保证。 |
| 本地账号、预算、授权码保护与隔离演示 | DPAPI 只保护保存的授权码；名单及正文未整体加密，demo 不真实投递。 |
| Windows 当前用户安装与本地服务 | loopback 会话保护不是公网登录、多租户权限或服务器部署能力。 |

本轮账号勾选持久化使用后端 SQLite `preferences`，经 `GET/PUT /api/account-selection` 读取和保存账号 ID，不保存授权码。桌面窗口保持隐私模式和动态 loopback 端口，不能用 localStorage 作为跨重开依据。源码跨进程 DPAPI 与偏好测试、浏览器重载及模式隔离已通过；隔离安装 EXE 的两次重开已确认账号授权码和勾选恢复。

历史安装故障涉及非锚定 `runtime\*` 排除规则漏装 `Python.Runtime.dll`，以及未闭合 script/style 影响退订纯文本解析。相关回归与锚定排除规则继续保留。README 已引用新的 0.2.1 源码实测截图，旧截图保留；它们不证明新版安装包通过验收。

## 2. 产品判断

保留本地、自有 SMTP 和中文名单流程，把“核对范围、冻结任务、预览内容、处理结果”做成连续操作。不扩展公网托管、多租户、CRM、自动跟进或投递追踪；不以“不封号”“必进主收件箱”或“永不重复”作为承诺。

**发送策略。** 以下源码行为已由替身传输与时钟测试验证，不代表真实投递效果：

- 默认预算为每账号 **6 封/分钟、200 次/日**，由软件自行选择，不是 Gmail、Yahoo、QQ 或 163 的阈值，也不是收件箱投递保证。日账本跨任务保存，测试发送、失败尝试和重试也计数。
- 以平稳间隔执行，默认至少约 10 秒，不积攒额度后突发发送；多账号不用于规避限制。依据是 [Gmail 发件人指南](https://support.google.com/mail/answer/81126)对稳定速率、监控响应和遇拒后减量的建议，以及 [Yahoo 发件最佳实践](https://senders.yahooinc.com/best-practices)对收件人意愿、身份验证和声誉的要求。**6/200 是本软件决策，并非这些指南给出的数值。**
- 对普通可重试 SMTP 4xx，第一次和第二次连续发生后对**整个任务**退避 30 秒、120 秒；第三次暂停。明确返回 `4.7.28` 时立即暂停，保存至少 600 秒的账号等待期限，重启或新建同账号任务仍受约束，之后需人工继续；认证/策略拒绝也暂停，不自动切换账号绕限流。其他服务商的要求仍须按实际响应判断。
- 提交结果不明（unknown／待确认，账本状态 `uncertain`）不自动重试。操作者先核对服务商发送记录或收件人情况，再明确选择重发；Message-ID 仅用于追踪，不能防止重复投递。

**投递与分类。** SPF、DKIM、DMARC、发件域/IP 声誉和投诉会影响接收，通常须由邮箱服务商或域名管理员配置；客户端放慢发送不替代这些条件。[Gmail 分类说明](https://support.google.com/mail/answer/3094499)将促销邮件列为收件箱的 Promotions 分类，因此进入“推广/营销”标签不等于进入垃圾箱，也不等于发送失败。

**商业用途与退订。** 编辑区不再展示“用途”和“名单来源”。更多发送选项中的商业广告开关映射现有 `purpose`：开启后补充 `AD` 并强制退订联系方式，普通通知可单独选择是否附加退订信息。旧 `source_note` 仅作兼容备注保留，不是授权证明，也不再必填。

[工信部《互联网电子邮件服务管理办法》](https://www.miit.gov.cn/zcfg/xxtxl/art/2009/art_d17e4e918c5a458f92ad087bee740a63.html)对商业广告的明确同意、广告标识、拒收和有效联系方式作出规定。软件开关不替代这些责任；回复/mailto 加人工排除不等于自动一键退订，本版不声称取得合规证明。
